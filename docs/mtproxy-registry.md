# Реестр MTProxy: устройство

Сервер сам ведёт список MTProxy, проверяет их и переключает боты на рабочий. Адреса приходят из опций и файла
при старте и от ботов: из постов каналов, пересланных сообщений, команд администратора.
Описание для пользователей — в [README](../README.md#mtproxy), здесь — как это устроено и почему.

## Термины

- **Реестр** — список прокси сервера, общий для всех его ботов.
- **Активный прокси** — тот, через который сейчас подключены все боты сервера.
- **Проверка** — `testProxy` TDLib: подключение к дата-центру 2 через прокси и обмен ключами с проверкой RSA-ключа
  Telegram, таймаут 10 секунд. Прокси, который только принимает соединения, проверку не проходит. Время успешной
  проверки — пинг (сглаживается: 0,7 старого и 0,3 нового).

## Код

- `telegram-bot-api/MTProxy.{h,cpp}` — разбор ссылок `tg://proxy`, `https://t.me/proxy` и `host:port:secret`,
  поиск ссылок в тексте, опции реестра.
- `telegram-bot-api/MTProxyManager.{h,cpp}` — актор реестра: хранение, методы, проверки, переключение.
- `ClientManager` создаёт `MTProxyManager` при старте и передаёт ему запросы методов реестра до создания клиента бота,
  поэтому методы работают без связи с Telegram.
- `Client` регистрируется в `MTProxyManager` при старте, сообщает о состоянии соединения и успешной авторизации,
  получает прокси через `set_mtproxy` (`addProxy` с `enable=true` или `disableProxy`, затем удаление выключенных
  прокси из базы TDLib бота) и снимается с учёта при закрытии.

## Опции

| Опция | Переменная | По умолчанию | Смысл |
|---|---|---|---|
| `--mtproxy` | `TELEGRAM_MTPROXY` (список через пробел) | | можно повторять; источник `option` |
| `--mtproxy-file` | `TELEGRAM_MTPROXY_FILE` | | по одной ссылке в строке, `#` — комментарий; источник `file`; перечитывается перед проверкой, если изменился |
| `--mtproxy-admins` | `TELEGRAM_MTPROXY_ADMINS` | | ID ботов через запятую, которым разрешены методы |
| `--mtproxy-check-interval` | | 600 | период проверки всех адресов, секунд |
| `--mtproxy-switch-timeout` | | 60 | сколько бот может быть без связи до переключения, секунд |
| `--mtproxy-expire` | | 72 | адрес от ботов, не работающий столько часов, удаляется |
| `--mtproxy-max` | | 200 | предел размера реестра |

## Хранение

`<dir>/mtproxy.json`, запись атомарная. Файл не создаётся, пока реестр не используется.

```json
{
  "active_id": 7,
  "next_id": 12,
  "admin_token_hashes": [{"bot_id": 123456, "hash": "sha256 токена в hex"}],
  "proxies": [
    {
      "id": 7, "server": "proxy.example.com", "port": 443, "secret": "ee...",
      "sources": ["option", "channel:-1001234567890/45", "bot:123456"],
      "added_date": 1759750000, "last_check_date": 1759753600, "last_success_date": 1759753600,
      "last_error": "", "failures_in_row": 0, "ping": 0.231
    }
  ]
}
```

- Секрет хранится нормализованным (base64url для `ee`, hex для остальных), поэтому один прокси, записанный по-разному,
  попадает в реестр один раз; повторное добавление дописывает источник.
- Источники `option` и `file` при старте берутся заново из опций и файла: адрес, у которого не осталось источников,
  удаляется. Такие адреса нельзя удалить методом, на них не действуют `--mtproxy-expire` и `--mtproxy-max`.
- Идентификаторы не переиспользуются.

## Методы

`POST /bot<token>/<method>`, параметры в JSON или form, ответ в формате Bot API. Имена регистронезависимы.

- `addMTProxies(links, source?)` — `links` — массив строк (или одна строка в form); в каждой ищутся все ссылки
  `tg://proxy?...`, `tg:proxy?...`, `[https://][www.]t.me|telegram.me|telegram.dog/proxy?...`; строка без ссылок
  и пробелов разбирается как `host:port:secret`. Строка без ссылок попадает в `errors`. `source` по умолчанию `bot:<id>`,
  не длиннее 128 символов, `option` и `file` запрещены. Новые адреса проверяются сразу.
  Результат: `{"added", "known", "ids", "errors": [{"link", "error"}]}`.
- `getMTProxies()` — `active_id`, `bot_count`, `connected_bot_count`, `is_checking`, `proxies` (записи реестра
  и `link`, `secret_type`, `domain`, `state`, `is_active`).
- `setMTProxy(id)` — переключает сразу, отменяя идущее автоматическое переключение.
- `removeMTProxy(id)` — удаляет адрес от ботов; если он активный, сервер выбирает новый как при переключении.
- `checkMTProxies()` — запускает проверку всех адресов, если она не идёт.

## Доступ

- Без `--mtproxy-admins` методы отвечают `403`.
- Одного ID в токене мало: токен `<id>:<что угодно>` подделывается. Когда бот из списка авторизуется в Telegram,
  сервер запоминает SHA-256 его токена и дальше сравнивает с ним. Сравнение локальное, поэтому методы работают и без связи
  с Telegram; но первый раз связь нужна — её дают `--mtproxy` и `--mtproxy-file`.
- Если токен перевыпущен, запоминается новый после авторизации с ним; старый перестаёт подходить.

## Проверка

- Служебный клиент TDLib создаётся при первой проверке и не инициализируется: `testProxy` работает до
  `setTdlibParameters`, поэтому ему не нужны ни база, ни `api_id`.
- Все адреса проверяются при старте и затем раз в `--mtproxy-check-interval`, до 8 одновременно.
- Состояния: `unchecked`, `working` (последняя проверка успешна), `failing`.
- Если бот подключился через активный прокси, тот считается рабочим, даже если проверка его не прошла
  (проверка идёт к дата-центру 2, бот может работать с другим).
- После проверки удаляются адреса от ботов, которые не работают и не работали дольше `--mtproxy-expire`.
- При добавлении сверх `--mtproxy-max` удаляется неработающий адрес, который дольше всех не работал;
  если таких нет — адрес не добавляется.

## Переключение

Раз в секунду сервер проверяет признаки того, что активный прокси не работает:

- какой-то бот без связи (`updateConnectionState` не `Ready` и не `Updating`) дольше `--mtproxy-switch-timeout`,
  считая от последнего переключения;
- нет ни одного бота на связи, а активный прокси не прошёл две проверки подряд.

Выбор нового:

1. Кандидаты — рабочие адреса, кроме активного и тех, что отказали, будучи активными, за последние 10 минут; по пингу.
2. Кандидат проверяется прямо перед переключением; не прошёл — следующий.
3. Если не прошёл никто — запускается проверка всех адресов, а боты переводятся на следующий адрес по порядку
   идентификаторов. Так перебор идёт раз в `--mtproxy-switch-timeout`, пока что-то не заработает.

Пока активный прокси работает, сервер не переключается, даже если есть быстрее. Каждое переключение пишется в лог
с причиной. При переключении TDLib переподключается и сам догружает пропущенные обновления.

## Тесты

`tests/mtproxy_test.py` и `tests/mtproxy_registry_test.py` работают без Telegram: поддельные MTProxy записывают
соединения TDLib и закрывают их. Поэтому все проверки в тестах неуспешны, а путь «кандидат прошёл проверку» тестами
не покрыт — его нужно проверять с настоящими прокси.

## Пока не сделано

- Прямое подключение без прокси как кандидат (`--mtproxy-direct`): для проверки нужен инициализированный клиент TDLib.
- Состояние реестра на странице статистики (`--http-stat-port`).
- Бот-сборщик ссылок из каналов: пример в laser_tele.
